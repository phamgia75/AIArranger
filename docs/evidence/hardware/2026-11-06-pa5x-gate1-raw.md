## Conclusions

- **Gate 1's 0 note events were not a USB or engine fault:** the same port now delivers notes. The likely reason, still a hypothesis: Upper 1 was not active then, and/or the chords were played with Lower, which has no MIDI OUT channel under "Hieu" and so is never sent.
- **Channel-routing mismatch with the engine's opt-in Pa5X roles:** `defaultPresetKeyboardRoles()` reads chords from **ch 4 (Lower)**, but this preset sends nothing on ch 4. With those roles enabled, the engine would see no chord input. This is a configuration mismatch, not a detector defect, and no engine code was changed.
- **Chord detection is still untested on hardware.** Ways forward:
  - (a) **No setting change:** chords played on Upper 1 across the keyboard, with `listen --channel 1 --split 128`;
  - (b) **Needs authorization:** assign Lower to a MIDI OUT channel, then test with the split.
